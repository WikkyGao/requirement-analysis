# 输入文档格式示例

> 本文件展示各类输入文档的标准格式，帮助 agent 正确解析和提取。

---

## Markdown 格式

```markdown
# 用户管理系统需求

## 用户管理

### 用户注册
- 支持邮箱注册
- 需要验证邮箱
- 密码最少8位

### 用户登录
- 支持账号密码登录
- 支持记住密码

## 订单管理

### 创建订单
- 选择商品
- 填写收货地址
- 选择支付方式

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| product_id | string | 是 | 商品ID |
| quantity | integer | 是 | 数量 |
| address | string | 是 | 收货地址 |
```

**解析规则**: `##` → 模块，`###` → 功能，列表 → 功能详情，表格 → 字段定义

---

## Excel 格式

**功能清单表**:

| 模块 | 功能名称 | 功能描述 | 优先级 | 负责人 |
|------|----------|----------|--------|--------|
| 用户管理 | 用户注册 | 新用户注册账号 | 高 | 张三 |
| 用户管理 | 用户登录 | 账号密码登录 | 高 | 张三 |
| 订单管理 | 创建订单 | 用户下单购买商品 | 高 | 李四 |
| 订单管理 | 订单查询 | 查看历史订单 | 中 | 李四 |

**数据字典表**:

| 表名 | 字段名 | 类型 | 必填 | 说明 |
|------|--------|------|------|------|
| user | id | uuid | 是 | 主键 |
| user | username | varchar(50) | 是 | 用户名 |
| user | email | varchar(100) | 是 | 邮箱 |
| order | id | uuid | 是 | 主键 |
| order | user_id | uuid | 是 | 外键 |
| order | total_amount | decimal(10,2) | 是 | 总金额 |

**解析规则**: 第一行 → 表头，按列名映射到功能字段

## Word (.docx) 格式

```
用户管理系统需求文档

1. 用户管理
  1.1 用户注册
    支持新用户通过邮箱注册账号，注册后需要验证邮箱。
  1.2 用户登录
    用户通过账号密码登录系统，支持记住密码功能。

2. 订单管理
  2.1 创建订单
    用户选择商品后填写收货地址和支付方式完成下单。
```

**解析规则**: 数字编号 → 层级结构，正文 → 功能描述

## 思维导图格式

```
用户管理系统 (根节点)
├── 用户管理 (一级节点 → 模块)
│   ├── 用户注册 (二级节点 → 功能)
│   │   ├── 邮箱注册 (叶子 → 详情)
│   │   └── 密码验证 (叶子 → 详情)
│   └── 用户登录 (二级节点 → 功能)
│       ├── 账号密码 (叶子 → 详情)
│       └── 记住密码 (叶子 → 详情)
└── 订单管理 (一级节点 → 模块)
    ├── 创建订单 (二级节点 → 功能)
    └── 订单查询 (二级节点 → 功能)
```

**解析规则**: 根节点 → 主题，一级 → 模块，二级 → 功能，叶子 → 详情

## 统一中间格式

所有格式解析后统一为以下 JSON 结构：

```json
{
  "id": "用户管理-用户注册",
  "name": "用户注册",
  "description": "支持新用户通过邮箱注册账号",
  "module": "用户管理",
  "priority": "high",
  "fields": [
    {
      "name": "email",
      "type": "string",
      "required": true,
      "description": "邮箱地址"
    }
  ],
  "source": {
    "document": "需求.md",
    "priority": 1
  }
}
```

**ID 生成规则**: `{模块名}-{功能名}`，中文直接使用，英文用 kebab-case

## 功能清单（反推需求）

当用户只提供功能名称列表时，需要通过反推补充完整需求。

**输入示例**:

```
功能清单：
- 用户注册
- 用户登录
- 查看订单
- 申请退款
```

**反推分析**:

```json
{
  "input_type": "feature_list",
  "inferred_context": {
    "domain": "电商",
    "user_roles": ["普通用户", "管理员（待确认）"],
    "business_flow": "注册→登录→浏览→下单→支付→查看→退款"
  },
  "missing_features": [
    "用户退出",
    "购物车",
    "商品浏览",
    "支付功能",
    "订单状态管理",
    "退款审批（待确认）"
  ],
  "questions": [
    {"priority": "🔴", "question": "是否需要购物车功能？"},
    {"priority": "🔴", "question": "退款由谁审批？自动还是人工？"},
    {"priority": "🟡", "question": "是否需要管理员后台？"},
    {"priority": "🟡", "question": "订单有哪些状态？"},
    {"priority": "🟢", "question": "是否需要消息通知？"}
  ]
}
```

**处理原则**:
1. 不假设用户需要哪些隐含功能，而是列出来让用户确认
2. 每个追问附带建议选项，降低回答成本
3. 标注优先级，🔴 必须回答的先问
