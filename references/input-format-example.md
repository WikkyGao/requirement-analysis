# 输入文档格式示例

> 本文件展示各类输入文档的标准结构，帮助理解不同格式的呈现方式。
> 解析逻辑已封装在 `scripts/parse_document.py` 中，此处仅展示格式示例作为语义参考。

---

## Markdown 格式

```markdown
# 用户管理系统需求

## 用户管理

### 用户注册
- 支持邮箱注册
- 需要验证邮箱
- 密码最少8位

### 用户登录
- 支持账号密码登录
- 支持记住密码

## 订单管理

### 创建订单
- 选择商品
- 填写收货地址
- 选择支付方式

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| product_id | string | 是 | 商品ID |
| quantity | integer | 是 | 数量 |
| address | string | 是 | 收货地址 |
```

**典型结构**: `##` → 模块分组，`###` → 功能项，列表 → 功能详情，表格 → 字段定义

## Excel 格式

**功能清单表**:

| 模块 | 功能名称 | 功能描述 | 优先级 | 负责人 |
|------|----------|----------|--------|--------|
| 用户管理 | 用户注册 | 新用户注册账号 | 高 | 张三 |
| 用户管理 | 用户登录 | 账号密码登录 | 高 | 张三 |
| 订单管理 | 创建订单 | 用户下单购买商品 | 高 | 李四 |
| 订单管理 | 订单查询 | 查看历史订单 | 中 | 李四 |

**数据字典表**:

| 表名 | 字段名 | 类型 | 必填 | 说明 |
|------|--------|------|------|------|
| user | id | uuid | 是 | 主键 |
| user | username | varchar(50) | 是 | 用户名 |
| user | email | varchar(100) | 是 | 邮箱 |
| order | id | uuid | 是 | 主键 |
| order | user_id | uuid | 是 | 外键 |
| order | total_amount | decimal(10,2) | 是 | 总金额 |

**典型结构**: 第一行为表头，按列名映射到功能字段。多 sheet 分别对应功能清单/数据字典。

## Word (.docx) 格式

```
用户管理系统需求文档

1. 用户管理
  1.1 用户注册
    支持新用户通过邮箱注册账号，注册后需要验证邮箱。
  1.2 用户登录
    用户通过账号密码登录系统，支持记住密码功能。

2. 订单管理
  2.1 创建订单
    用户选择商品后填写收货地址和支付方式完成下单。
```

**典型结构**: 数字编号层级 → 标题层级，正文 → 功能描述

## 思维导图格式

```
用户管理系统 (根节点)
├── 用户管理 (一级节点)
│   ├── 用户注册 (二级节点)
│   │   ├── 邮箱注册 (叶子)
│   │   └── 密码验证 (叶子)
│   └── 用户登录 (二级节点)
│       ├── 账号密码 (叶子)
│       └── 记住密码 (叶子)
└── 订单管理 (一级节点)
    ├── 创建订单 (二级节点)
    └── 订单查询 (二级节点)
```

**典型结构**: 根节点 → 系统主题，一级节点 → 模块，二级节点 → 功能，叶子节点 → 功能详情

## 统一中间格式

所有格式解析后统一为以下 JSON 结构：

```json
{
  "id": "用户管理-用户注册",
  "name": "用户注册",
  "description": "支持新用户通过邮箱注册账号",
  "module": "用户管理",
  "priority": "high",
  "fields": [
    {
      "name": "email",
      "type": "string",
      "required": true,
      "validation": "邮箱格式",
      "default": "",
      "description": "邮箱地址"
    }
  ],
  "actions": [
    {
      "name": "发送验证码",
      "condition": "email填写且格式正确",
      "behavior": "发送6位验证码",
      "error_handling": "格式错误提示"
    }
  ],
  "interactions": ["邮箱输入框失焦时实时校验"],
  "acceptance_criteria": ["输入合法邮箱可成功注册"],
  "source": {"document": "需求.md", "priority": 1}
}
```

**ID 生成规则**: `F-{模块名}-{功能名}`，中文直接使用，英文用 kebab-case

## 功能清单类型的输入（参考）

当用户只提供功能名称列表时，需要通过 LLM 交互（内联在 SKILL.md Task 1.5 中）反推补充完整需求。

**输入示例**:

```
功能清单：
- 用户注册
- 用户登录
- 查看订单
- 申请退款
```

**反推思路**: 从功能列表推断业务领域、用户角色、业务流程、隐含功能和缺失信息，然后逐批追问用户确认。

> 反推需求的具体交互逻辑见 SKILL.md `<task name="对话式需求提取">`。
